# 25-minute Adobe role-play prep

## Suggested arc
- 0–3 minutes: open, validate goals
- 3–8 minutes: discovery of current workflows, failure points, comparison criteria
- 8–16 minutes: interactive demo (~8 minutes), adjust when interrupted
- 16–20 minutes: validate what resonated and discuss technical/security pushback
- 20–25 minutes: stakeholders, evaluation proposal, next step

## Discovery questions (pick 3–4, do not interrogate)
1. Where do your developers prefer Claude Code or Copilot today, and why?
2. What's the most expensive friction in the existing Photoshop/Creative Cloud workflows: understanding code, implementing changes, debugging or reviews?
3. Which repos, languages and team conventions create the most context-management problems?
4. What would convince you that Cursor improves developer outcomes without hurting code quality?
5. Who owns developer tooling decisions and security approval for a broader evaluation?

## Likely pushback
- "Claude Code does this": agree it can; highlight observable workflow ergonomics and offer a controlled same-task comparison rather than exaggeration.
- "Toy repo proves nothing about monorepos": agree; propose testing a production-representative but sanctioned repo, bounded use cases and agreed evaluation measures.
- "I don't want to standardize": frame standardization as optional; see whether shared guardrails and repeatable workflows reduce overhead without forcing every developer to switch.
- "How do you pick models?": discuss latency, capability, cost, data policy and empirically benchmark approved models on actual tasks; explain Auto vs manual selection.
- "Security?": surface Privacy Mode, provider/model routing, approval/sandbox controls, admin policies and the need for an actual enterprise assessment.
- "What value?": suggest baseline-to-pilot comparison for time-to-completion, review rework, adoption, escaped defects and qualitative satisfaction; no made-up ROI.

## Proposed next step
Define a 2–4-week controlled evaluation (proposed, not an existing Cursor program) across 1–2 teams with common tasks, baseline measures, security sign-off, named engineering sponsor and decision criteria. Confirm who would participate and book a scoped follow-up.
